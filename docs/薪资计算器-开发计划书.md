## 一、项目背景与目标

### 1.1 痛点

- 现有在线薪资计算器字段固定，无法增删收入项/扣除项，覆盖不了「补贴+项目奖+年终奖」等复杂薪酬结构。
- 五险一金缴费基数存在「上下限封顶托底」与「按应发/按约定基数」两种口径，多数工具不支持切换。
- 个税采用**累计预扣预缴法**，月薪相同的两个人因年中入职、年终奖计税方式不同，全年到手差异很大，工具普遍算不准。
- 结果只看「到手多少」，缺少「月薪 / 年薪 / 月度趋势 / 结构占比」的可视化与导出。
- 数据资产无人托管：在线工具把数据放在浏览器或云端——前者清缓存、换浏览器即丢，后者存在隐私顾虑；用户需要数据真正落在本机、可备份、可迁移。

### 1.2 目标（V1）

| 编号 | 目标 | 验收口径 |
| --- | --- | --- |
| G1 | 全链路计算准确 | 与手工 Excel 核算结果误差 ≤ 0.01 元 |
| G2 | 表格组成项可自定义 | 用户可勾选/排序/重命名列，配置本地持久化并支持预设模板 |
| G3 | 月薪 + 年薪双视角 | 输入月薪自动推全年 12 个月明细；输入年薪自动反推月薪 |
| G4 | 政策可配置 | 城市社保比例、基数上下限、专项附加扣除标准全部走配置层，改配置不改代码 |
| G5 | 本地持久化可靠 | 应用崩溃、强杀进程、重启电脑后，方案、列配置、设置恢复到最近一次成功保存（最多丢失 2 秒内编辑）；写入采用原子替换，失败有降级与可见提示；数据固定存放在应用数据目录并可一键打开 |
| G6 | 导入导出与备份可用 | 支持全量/单方案/配置三种 JSON 导出与导入、CSV 明细导出，全部走系统原生文件对话框；非法文件被拦截且不破坏现有数据；导入前自动快照，可撤销 |
| G7 | 桌面交付与离线运行 | 产出可安装的 Windows x64 安装包（NSIS/MSI），安装后完全离线运行、无任何网络请求；数据目录、版本号、日志入口在应用内可见 |

### 1.3 非目标（V1 不做）

- 不做用户体系、云同步与服务端存储（桌面单机应用 + 本地文件）。
- 不做各城市社保政策的实时爬取（改为配置下发 + 版本号提示）。
- 不做个税年度汇算清缴的完整申报流程（仅做测算）。
- 不做加密存储（本机明文，界面需明确提示；共享设备场景由「一键清除」兜底）。
- V1 仅交付 **Windows 10/11 x64**；macOS/Linux 构建列入 V1.1（代码复用，但需独立构建、签名与测试）。
- 不做自动更新（V1.1）、不做移动端、不做浏览器在线版作为交付物；开发期保留浏览器调试适配器，不随安装包发布。
- 不做 xlsx 多 Sheet 导出与分享链接（列入 V1.1，见第十一章）。

## 二、需求拆解

### 2.1 输入区

**A. 收入项（可增删、可排序、可启用/停用）**

| 默认项 | 类型 | 说明 |
| --- | --- | --- |
| 基本工资 | 月度固定 | 应发工资主体 |
| 岗位/绩效工资 | 月度固定 | |
| 加班费 | 月度浮动 | |
| 各类补贴（交通/餐补/通讯/住房） | 月度固定 | 部分补贴属免税/不并入缴费基数，需提供「是否计入社保基数」「是否计税」开关 |
| 项目奖金 | 月度/一次性 | 支持指定发放月份 |
| 年终奖（13薪/绩效奖） | 年度一次性 | 支持「单独计税」与「并入综合所得」两种口径并对比 |
| 股权/期权归属收益 | 年度一次性 | V1 仅按综合所得口径简化处理 |

**B. 五险一金**

- 参保城市（决定比例与基数上下限，可切换/自定义）。
- 缴费基数口径：`按应发工资` / `按上年度月均` / `手动指定` / `按下限托底`。
- 基数上下限自动封顶托底（可手动覆盖）。
- 险种：养老、医疗（含大病）、失业、工伤、生育（已并入医疗的地区按城市配置）、住房公积金。
- 每项支持单独开关与比例覆盖；展示个人/单位双边金额；公积金单位与个人比例可不同。
- 补充公积金、企业年金（V1.1）。

**C. 专项附加扣除及其他扣除**

- 子女教育、3 岁以下婴幼儿照护、继续教育、住房贷款利息、住房租金（按城市档位）、赡养老人（独生子女/分摊）、大病医疗。
- 个人养老金（年度限额）、商业健康险、税延养老、公益捐赠。
- 房租与房贷互斥校验（同一年度不可同时享受）。

**D. 全局设置**

- 计算年度、入职月份（影响累计减除费用月份数）。
- 是否按 12 个月平均、年终奖发放月份、年终奖计税方式。

### 2.2 计算与输出区

- **结果卡片**：应发合计、五险一金个人合计、单位成本、应纳税所得额、个税、到手工资、实发替代率（到手/应发）。
- **月度明细表**：1–12 月逐月列（收入、各项扣除、专项附加、累计预扣税额、当月个税、当月到手）。
- **年度汇总表**：各项年度合计占比。
- **图表**：月度到手趋势折线、收入结构饼图、五险一金占比。
- **对比模式**：两套方案（如年终奖两种计税方式、两个 Offer）并排对比差额。

### 2.3 表格自定义（核心差异化功能）

- 列配置抽屉：勾选显示/隐藏、拖拽排序、自定义列宽、重命名表头。
- 支持「自定义收入列」映射为表格列（新增收入项自动出现在列配置中）。
- 预设模板：`极简`（应发/五险一金/个税/到手）、`HR 全量`、`财务口径`、`个人理财`。
- 列配置随根文档持久化，并记录当前套用的 `presetId`；支持单独导出/导入列配置。

### 2.4 数据管理（本地持久化与导入导出）

| 能力 | 说明 | 验收口径 |
| --- | --- | --- |
| 自动保存 | 输入变更后防抖 400ms 写入磁盘，窗口最小化/关闭前立即落盘 | 强杀进程、重启电脑后数据与界面状态一致 |
| 方案管理 | 新建/复制/重命名/删除/切换，每个方案独立保存输入 | 删除需二次确认，10 秒内可撤销 |
| 快照备份 | 每日首次修改自动快照（保留 14 份）+ 手动备份点（20 份） | 可查看时间、方案数与大小并恢复，恢复前自动再备份 |
| 全量导出 | 单文件包含方案、列配置、预设、自定义城市、设置 | 导出→导入后语义等价 |
| 单方案/配置导出 | 便于分享与迁移，不含无关方案与薪资金额 | 配置导出文件不含金额字段 |
| 导入 | 系统文件对话框 + 拖拽到窗口；解析后先预览再确认 | 非法文件明确报错，现有数据不变 |
| 清空数据 | 输入确认词后清空，清空前自动备份 | 可从快照恢复 |
| 存储状态 | 显示数据目录、状态文件大小、最后保存时间、异常原因 | 异常状态用户可见，可一键打开目录 |
| 数据目录 | 显示 `%APPDATA%` 下的实际路径，提供「打开所在文件夹」 | 用户可直接备份/拷贝整个目录 |
| 单实例 | 重复启动时聚焦已有窗口，不产生第二个写入者 | 不会出现双进程同时写状态文件 |

## 三、核心计算模型

### 3.1 数据流

```text
输入项(收入/社保/扣除/设置)
   │
   ├─► 归一化：按月展开 → IncomeByMonth[]
   │
   ├─► 社保基数计算：clamp(base, lower, upper)
   │      └─► 个人/单位五险一金明细 SocialInsuranceDetail
   │
   ├─► 累计预扣预缴（逐月滚动）
   │      cumulativeTaxable = Σ收入 - Σ免税收入 - 5000×N
   │                          - Σ专项扣除(社保个人部分) - Σ专项附加扣除 - Σ其他扣除
   │      tax(N) = max(0, round2(bracket(cumulativeTaxable)) - Σ已预缴)
   │      注：N 为「截至本月在本单位的任职受雇月份数」，非自然月序
   │
   ├─► 年终奖：单独计税 与 并入综合所得 双口径计算，取较优并提示
   │
   └─► 到手 = 收入 - 社保个人部分 - 个税
       单位总成本 = 应发 + 社保单位部分
```

### 3.2 关键公式

```text
月度到手 = 月度应发 - 五险一金(个人) - 当月个税
当月个税 = max(0, (累计应纳税所得额 × 预扣率 - 速算扣除数) - 累计已预扣税额)
累计应纳税所得额 = 累计收入 - 累计免税收入 - 5000×累计月份数
                   - 累计专项扣除 - 累计专项附加扣除 - 累计其他扣除
社保缴费额 = clamp(缴费基数, 下限, 上限) × 比例
年终奖单独计税 = 奖金 ÷ 12 查月度税率表 → 奖金 × 税率 - 速算扣除数
```

**口径补充（实现必须遵守）**

1. **累计月份数 N**：按在本单位的任职受雇月份数计，年中入职（如 7 月）当年最多计 6 个月，不得按自然月序。
2. **负税额处理**：某月按累计法算出的应预扣税额为负时，当月按 0 申报，不退税；多缴部分留待次年汇算清缴。后续月份继续用「累计应纳 - 累计已预扣」滚动，不得把负数带入累计已预缴。
3. **年终奖单独计税**：一个纳税年度内只能使用一次；选择单独计税时，奖金不并入当月累计综合所得。
4. **年终奖临界点**：奖金落在税率跳档区间（36,000 / 144,000 / 300,000 / 420,000 / 660,000 / 960,000）附近时，需提示「多发 1 元、到手减少」的区间，并给出两种计税方式对比。
5. **社保基数**：各险种按「城市 + 险种」独立 clamp，取整到分后再汇总；工伤、生育个人部分为 0 的城市按 0 计。
6. **个税尾差**：常规路径下，各月按分取整的预扣额由末月自然校正，全年合计等于按年度总额一次性计算的税额，无需额外补差。若中途发生「负税额按 0 处理」，全年已预缴可能略高于年度应纳税额，差额留待汇算清缴，**不得强行补扣或退款**；单测需分别覆盖这两种路径。

### 3.3 税率与扣除标准（配置化，附版本号）

- 综合所得预扣率表（7 级超额累进）与全年一次性奖金月度税率表：见「附录 A」。
- 基本减除费用：5000 元/月（60000 元/年）。
- 专项附加扣除标准（2023 年起）：
  - 婴幼儿照护 2000 元/月/孩；子女教育 2000 元/月/孩。
  - 继续教育 400 元/月（学历）或 3600 元/年（职业资格，取得当年一次性）。
  - 住房贷款利息 1000 元/月；住房租金 1500/1100/800 元/月（按城市档位）。
  - 赡养老人 3000 元/月（独生子女）；非独生子女分摊，每人 ≤1500 元/月。
  - 大病医疗：自付超过 15000 元部分据实扣除，年度限额 80000 元。该项**仅在年度汇算时扣除**，不得计入月度累计预扣；V1 只在年度测算中体现并标注「汇算时享受」。
- 个人养老金扣除上限：12000 元/年。
- 全年一次性奖金单独计税政策延续至 2027-12-31，配置中带 `validUntil` 字段，过期后在 UI 提示。
- 社保缴费基数上下限通常为上年度全口径城镇单位就业人员平均工资的 60%–300%，公积金另有上下限，全部写入城市配置。

> **实现要求**：以上全部数值存于 `src/config/`，带 `policyVersion` 与 `effectiveDate`，禁止硬编码散落在计算逻辑中。

### 3.4 精度策略

- 计算内核全程使用 `decimal.js`，避免 `0.1 + 0.2` 类浮点误差。
- 各险种金额按「四舍五入到分」独立取整后再求和（与各地社保口径一致），个税保留 2 位小数。
- 展示层统一 `toFixed(2)`；导出 CSV 保留原始数值（最多 2 位小数、不加千分位）。
- 持久化金额统一为 `number`，限制最多 2 位小数；计算前一律 `new Decimal(String(v))`，禁止直接对浮点做累加。

### 3.5 数据单位约定（全局强制）

| 数据 | 类型 | 单位/范围 | 说明 |
| --- | --- | --- | --- |
| 金额 | `number` | 元，2 位小数，`[0, 1e9)` | 不接受千分位字符串、货币符号 |
| 费率 | `number` | 百分比数值，`[0, 100]` | `8` 表示 8%，UI 与配置一致，内核只除一次 100 |
| 月份 | `number` | 整数 `1–12` | 发放月份、入职月份 |
| 年度 | `number` | 整数，如 `2026` | |
| 日期时间 | `string` | ISO 8601 带时区 | `2026-10-26T14:30:00+08:00` |
| ID | `string` | 32–64 字符 | `crypto.randomUUID()`，带类型前缀更佳 |

## 四、技术选型

### 4.1 选型对比与结论

| 维度 | 候选 | 结论 | 理由 |
| --- | --- | --- | --- |
| 桌面壳 | Tauri 2 / Electron | **Tauri 2** | 应用本体约 10–15MB、内存占用低、复用系统 WebView2；Rust 侧适合做原子文件写、备份轮转与系统对话框。内置离线 WebView2 后安装包约 100–130MB，仍小于 Electron 的常见体积 |
| 框架 | Vue 3 / React 19 | **Vue 3（`<script setup>`）** | 契合团队既有规范；模板 + 组合式 API 在表单密集场景代码量更少；体积更小 |
| 语言 | TS / JS | **TypeScript strict（前端） + Rust stable（壳层）** | 业务逻辑全在 TypeScript；Rust 只承担文件 IO、路径与系统集成，禁止写业务规则 |
| 前端构建 | Vite / Webpack | **Vite 6** | Tauri 官方模板与 Vite 集成成熟，秒级冷启动与 HMR |
| UI 库 | Element Plus / Naive UI / Ant Design Vue | **Element Plus** | 表格（`el-table`）能力最全：固定列、合并表头、多级表头、虚拟滚动，正好匹配「自定义列」诉求；生态成熟 |
| 状态 | Pinia / 自研 composable | **Pinia** | 方案对比、列配置属跨组件共享状态 |
| 持久化 | tauri-plugin-store / 自研 Rust 文件存储 | **自研 Rust 存储命令 + TS 适配器** | `plugin-store` 无法保证原子替换、备份轮转与损坏隔离；自研可用「临时文件 + rename + fsync」，并可用 `cargo test` 覆盖。前端保留 localStorage 适配器，仅用于浏览器调试 |
| 文件对话框 | tauri-plugin-dialog / 浏览器下载 | **tauri-plugin-dialog** | 原生打开/保存对话框，路径与覆盖确认交给系统；不再需要 Blob 下载与 File System Access API |
| 单实例 | tauri-plugin-single-instance / 自研锁 | **tauri-plugin-single-instance** | 避免双进程同时写状态文件；重复启动时聚焦已有窗口 |
| 运行时校验 | zod / valibot / 手写 | **zod** | 导入文件与本地状态均为不可信数据；zod 提供字段级错误路径与严格模式，兼作配置层校验 |
| 表格内核 | Element Plus 表格 / TanStack Table（headless） | **V1 用 Element Plus；列配置自研** | V1 不与 UI 库解耦，降低复杂度；列配置抽成 `useTableSchema`，后续可平滑迁移到 TanStack |
| 拖拽排序 | vuedraggable / sortablejs | **sortablejs（经 vuedraggable 封装）** | 列排序交互成熟稳定 |
| 图表 | ECharts / Chart.js | **ECharts 5 + vue-echarts** | 按需引入，折线/饼图/柱图覆盖全部诉求 |
| 数值计算 | decimal.js / big.js | **decimal.js** | API 丰富，支持四舍五入模式配置 |
| CSV | papaparse / 自研 | **自研 `toCsv`（约 60 行）** | 需精确控制 BOM、RFC 4180 转义与公式注入防护，引库反而要绕开其默认行为 |
| 工具库 | — | **VueUse、dayjs** | `useDebounceFn`、`useEventListener` 减少样板代码；不使用 `useStorage` 以免绕过持久化层 |
| 表单校验 | Element Plus 内置 async-validator | **内置** | 不额外引入 |

## 五、架构设计

### 5.1 分层原则

```text
config（静态政策数据，可版本化）
   ↓
core（纯函数计算内核 + 纯函数持久化逻辑，零框架依赖、100% 可单测）
   ↓
bridge（TS 适配器接口 → Tauri invoke / 浏览器调试实现）
   ↓
Rust commands（仅文件 IO、备份轮转、原生对话框；无业务规则）
   ↓
plugins / composables（把 core 结果接成响应式，防抖自动保存）
   ↓
stores（跨组件共享状态：方案、列配置、设置）
   ↓
components（只负责渲染与交互，不写业务规则）
```

**核心约束**：

- `src/core/` 内不得出现任何 `import from 'vue'` / UI 库 / `window` / `localStorage` / `@tauri-apps/*` 引用。
- 序列化、校验、迁移、导入计划（diff/合并）、CSV 生成全部是纯函数，放 `core/persistence/`。
- 组件不得直接调用 `invoke`、`localStorage` 或文件 API，一律经 store 与 `src/storage/bridge.ts`。
- Rust 层不实现薪资规则、不做数据格式演进；只接受已序列化字符串，负责安全落盘。IPC 命令面保持最小（见 6.14）。
- 浏览器调试适配器与 Tauri 适配器必须实现同一 `PersistenceBridge` 接口，保证核心逻辑不感知运行环境。

### 5.4 表格自定义实现方案

- `useTableSchemaStore` 维护 `ColumnSchema[]`：`{ key, label, group, visible, order, width, formatter, fixed }`。
- 表格列由 `computed(() => schema.filter(visible).sort(order))` 动态生成，配合 `<el-table-column v-for>` 渲染。
- 收入项变更时通过 `watch` 同步增删可选列（新增收入项默认可见，删除则移除列）。
- 列 Schema 以 `key` 为准做幂等同步：重复 key 保留首个、孤儿列自动清理并给出提示。
- 预设模板为 `config` 中的常量工厂函数（避免引用污染），支持「另存为我的预设」。
- 列配置与预设随根文档一起持久化，并参与全量导入导出。

## 六、本地持久化与导入导出

> 本章是 G5/G6 的实现依据。核心取舍：**本地优先、只存输入、单一根文档、版本先行、失败可解释、导入即不可信数据。**

### 6.1 设计原则

1. **本地优先，零网络**：数据写入本机应用数据目录；运行期不发起任何网络请求、不上报埋点，生产 CSP 禁止外联。
2. **只存输入，不存派生**：方案输入、列配置、预设、设置持久化；月度/年度计算结果在加载后重算，避免政策版本或公式升级后旧结果与新口径不一致。
3. **单一根文档 + 磁盘原子替换**：全部业务状态序列化为一棵树，由 Rust 以「临时文件 → fsync → rename」覆盖 `state.json`，避免「方案写成功、列配置写失败」的半状态，也避免断电留下半个 JSON。
4. **版本先行**：持久化结构带 `schemaVersion`；升级走迁移链，降级明确拒绝并保留原始文件。
5. **失败可解释**：磁盘满、无权限、文件损坏、导入非法，都必须有可见提示与出路（重试、导出、恢复），禁止静默丢数据。
6. **不可信输入**：导入文件按不可信数据处理——白名单字段、数量上限、无动态执行、渲染不用 `v-html`。
7. **壳层最小化**：Rust 只做文件 IO、备份轮转、原生对话框与单实例，不承载薪资规则；IPC 命令面保持最小并校验参数。

### 6.2 存储介质与适配器

| 介质 | 容量 | 优点 | 缺点 | 本项目定位 |
| --- | --- | --- | --- | --- |
| 应用数据目录文件 | 受磁盘剩余空间限制 | 真正落盘、可直接备份/拷贝、不受浏览器清缓存影响 | 需处理权限、磁盘满、同步盘冲突 | **V1 主存储**：`%APPDATA%\com.salarycalculator.app\` |
| 用户选择的导出路径 | 无限 | 可迁移、可分享 | 由用户管理 | 导入导出主通道（原生对话框） |
| 内存 | 会话级 | 一定可用 | 关闭即丢 | 单元测试；极端情况下临时会话（界面显著提示不可持久化） |
| `localStorage` | 约 5MB | 无壳层依赖、调试快 | 与桌面数据不一致 | **仅浏览器调试**，不进入发布包 |

所有读写经由统一 `PersistenceBridge` 接口（见 5.3），启动时按环境选择实现：

```ts
function createBridge(): PersistenceBridge {
  if (isTauri()) return createTauriBridge()          // 生产
  if (import.meta.env.DEV) return createLocalStorageBridge()  // 浏览器调试
  return createMemoryBridge()                        // 理论上不可达，兜底只读
}
```

启动时调用 `loadState()` 验证数据目录可读；首次启动若目录不存在则由 Rust 创建。写入探针失败（无权限、磁盘只读）时进入只读模式：允许查看与导出，禁止编辑保存，并在顶部常驻提示。

### 6.3 磁盘布局与数据分区

```text

├─ state.json                 # 根文档（唯一业务事实源）
├─ backups\
│  ├─ last-good.json          # 上一次成功保存的完整状态
│  ├─ daily\YYYY-MM-DD.json   # 每日首次修改快照
│  ├─ manual\<id>.json        # 用户手动备份点
│  └─ pre-import\<ts>.json    # 每次导入前的自动快照
├─ quarantine\<ts>.json       # 解析失败的原始内容（只读）
├─ ui.json                    # 非关键 UI 偏好，不参与导出
└─ logs\app.log               # 滚动日志，不含金额与姓名
```

| 文件 | 内容 | 写入时机 | 保留策略 |
| --- | --- | --- | --- |
| `state.json` | 根文档：meta + 方案 + 列配置 + 预设 + 自定义城市 + 设置 | 防抖保存、窗口关闭前 | 始终保留，原子替换 |
| `backups/last-good.json` | 上一次成功保存的完整状态 | 每次成功保存前（由 Rust 复制旧文件） | 1 份 |
| `backups/daily/YYYY-MM-DD.json` | 当日首次修改的全量快照 | 每天首次保存 | 最近 14 份，超出淘汰最旧 |
| `backups/manual/<id>.json` | 手动备份点（含备注） | 用户点击「创建备份点」 | 最多 20 份，用户可删 |
| `backups/pre-import/<ts>.json` | 导入前状态 | 每次导入应用前 | 最近 10 份 |
| `quarantine/<ts>.json` | 解析失败的原始文本 | 数据损坏时 | 1 份，供导出诊断 |
| `ui.json` | 列宽以外的界面偏好（最近导出目录等） | 变更时 | 不参与导出 |

**注意**：不做多文件业务拆分。单根文档换来一致性与可原子替换，代价是每次保存全量序列化——状态 < 1.5MB 时预估写入 < 30ms，验收时以实测为准。`state.json.tmp` 只作为写入中间态存在，启动时若发现残留直接删除，不参与读取。

### 6.4 持久化数据模型

**根文档**（`state.json`）即 `AppState`（见 5.3），其中：

- `schemes` 用 `Record<id, SalaryScheme>`，避免数组顺序影响 diff；
- `tableSchema` / `presets` 为数组，`order` 字段决定展示顺序；
- `meta.schemaVersion` 是**唯一**的版本事实源；文件名不带版本号，版本迁移在数据层完成，不搬文件；
- 业务状态与 UI 偏好分离：`ui.json` 允许丢失，`state.json` 不允许。

**导入导出信封**：

```json
{
  "format": "salary-calculator-backup",
  "kind": "full",
  "schemaVersion": 1,
  "appVersion": "1.0.0",
  "policyVersion": "2026.10",
  "exportedAt": "2026-10-26T14:30:00+08:00",
  "checksum": "sha256:9f2c…",
  "payload": {
    "schemes": [],
    "activeSchemeId": null,
    "tableSchema": [],
    "presets": [],
    "customCities": [],
    "settings": {}
  }
}
```

**三种 `kind` 的 payload 结构**

| kind | payload | 说明 |
| --- | --- | --- |
| `full` | `{ schemes, activeSchemeId, tableSchema, presets, customCities, settings }` | 全量状态，**不含 `meta`**；导入时重建 `meta`（版本、时间、revision 归零后自增） |
| `scheme` | `{ scheme: SalaryScheme }` | 单方案，名称与输入完整保留 |
| `config` | `{ tableSchema, presets, customCities }` | 仅配置，不得包含任何金额/收入项字段；导出前断言 |

> `meta` 属于「本机安装状态」而非「用户数据」，不随文件迁移：导入端的 `schemaVersion` 以文件信封为准，本地版本始终取应用常量。

**序列化约束**

- 禁止出现 `undefined`、`NaN`、`Infinity`、函数、`Date` 对象、循环引用；保存前用 zod 校验一次（开发环境）并在序列化器中断言。
- 对象键按字典序输出 `canonicalStringify`，保证同一状态产生相同文本与校验和；导出文件用 2 空格缩进便于人读与 diff。
- `checksum` 为对 `payload` 规范化 JSON 的 SHA-256（Web Crypto，仅安全上下文可用；不可用时省略该字段，导入端按可选处理）。
- 时间戳与 `revision` 不参与语义比较（见 8.2 的往返测试口径）。

### 6.5 写入策略

```ts
async function persist(state: AppState): Promise<SaveOutcome> {
  const next = {
    ...state,
    meta: {
      ...state.meta,
      revision: state.meta.revision + 1,
      savedAt: new Date().toISOString(),
    },
  }
  const json = canonicalStringify(next)
  // Rust 侧：备份旧 state.json → 写 state.json.tmp → fsync → rename 覆盖
  const outcome = await bridge.saveState(json)
  if (outcome.ok) await maybeCreateDailySnapshot(json)
  return outcome
}
```

**Rust `save_state` 的原子性契约**（必须由 `cargo test` 覆盖）：

1. 确保数据目录与 `backups/` 存在；
2. 若 `state.json` 已存在，尽力复制为 `backups/last-good.json`；复制失败只记日志，不阻断本次保存；
3. 将新内容写入同目录的 `state.json.tmp`，`sync_all()` 落盘；
4. `rename(state.json.tmp, state.json)` 原子替换（Windows 使用 `MoveFileEx` 语义，可覆盖已存在文件）；
5. 若 rename 因杀毒软件/索引服务短暂占用失败，按 50ms / 150ms / 300ms 退避重试 3 次；
6. 返回 `{ ok, bytes, reason? }`；失败时 `state.json` 必须仍是上一个完整版本。

**触发时机**

| 触发 | 行为 |
| --- | --- |
| 任意输入/配置变更 | `debounce 400ms`，最长等待 2s 强制落盘 |
| 窗口失去焦点、最小化 | 立即 flush |
| 点击关闭按钮 | 拦截 `onCloseRequested`：先 `preventDefault()`，flush 成功后再 `destroy()`；失败则弹窗「重试 / 导出备份 / 仍要关闭」 |
| 方案切换/导入/清空/恢复快照 | 立即写入，不走防抖 |
| 保存失败 | 停止自动重试（瞬时占用除外），页头显示错误 + 「立即导出备份」按钮 |

**保存状态机**：`idle → dirty → saving → saved | failed`，状态在页头以图标与时间展示（已保存 / 保存中 / 保存失败）。保存失败时禁止继续静默累积，避免用户误以为已保存。

**磁盘满处理顺序**（`ENOSPC`）：淘汰最旧日快照 → 淘汰最旧手动备份（至少保留 1 份）→ 淘汰最旧 pre-import → 重试一次 → 仍失败则进入只读模式并引导导出。任何情况下不得删除 `state.json` 或 `last-good.json`。

### 6.6 版本与迁移

```ts
const SCHEMA_VERSION = 1
type Migration = (payload: unknown) => unknown

const MIGRATIONS: Record<number, Migration> = {
  // 2: (p) => { ... v1 → v2 ... },
}

function migrate(envelope: { schemaVersion: number; payload: unknown }): unknown {
  if (envelope.schemaVersion > SCHEMA_VERSION) {
    throw new SchemaTooNewError(envelope.schemaVersion)   // 明确拒绝，不猜测
  }
  let version = envelope.schemaVersion
  let payload = envelope.payload
  while (version < SCHEMA_VERSION) {
    const step = MIGRATIONS[version + 1]
    if (!step) throw new MissingMigrationError(version)
    payload = step(payload)
    version += 1
  }
  return payload
}
```

规则：

1. 迁移函数必须是**纯函数**，不得读写存储、不得依赖当前时间。
2. 每新增一版，必须同时提交：迁移函数 + 一个旧版样本 `tests/fixtures/state-v<N>.json` + 单测。
3. 旧迁移永不删除；`SCHEMA_VERSION` 只增不减。
4. 加载时先迁移再 zod 校验；迁移或校验失败都**不写盘**，把原文写入 `quarantine/<ts>.json` 并提示「导出诊断文件」。
5. 降级（文件版本 > 当前应用）直接拒绝，提示升级应用，绝不尝试部分读取。
6. Rust 层不感知 `schemaVersion`，只负责读写字符串；所有版本判断与迁移在 TypeScript 中完成。

### 6.7 单实例与外部改动检测

- 通过 `tauri-plugin-single-instance` 保证同一时刻只有一个进程写 `state.json`；用户重复启动时聚焦已有窗口，不新开窗口。V1 不做多窗口。
- 浏览器调试模式可能同时开多个标签页，但该模式不进入发布包，不为其实现同步协议。
- **外部改动检测**：数据是普通文件，可能被 OneDrive/网盘同步、用户手工编辑或其他工具改写。窗口获得焦点时（节流 5s）读取 `state.json` 的修改时间、大小与 `meta.revision`，与内存中最后保存值比较：
  - 一致 → 忽略；
  - 不一致且本页无未保存修改 → 提示「数据文件已被外部修改，是否重新加载？」；
  - 不一致且本页有未保存修改 → 冲突条：「重新加载（放弃本地）/ 保留本地并覆盖 / 先导出本地副本」。
- 不做字段级自动合并；选择覆盖前，把当前内存状态另存为 `backups/manual/external-conflict-<ts>.json`。
- 发布说明建议用户不要把应用数据目录放入实时同步盘；若必须同步，明确「同一时间只在一台机器编辑」。

### 6.8 故障与降级

| 场景 | 检测方式 | 处理 |
| --- | --- | --- |
| 数据目录不可读/无权限 | 启动时 `loadState` 失败 | 显示错误页：完整路径、错误码、「打开目录」「重试」「退出」；不加载空状态覆盖原文件 |
| 目录可读但不可写 | 写入探针失败 | 进入只读模式：可查看、可导出，禁止编辑；顶部常驻提示 |
| 磁盘空间不足 | `save_state` 返回 `disk-full` | 按 6.5 顺序裁剪备份后重试；仍失败则只读模式 + 引导导出到其他磁盘 |
| 文件被占用（杀毒/索引/同步盘） | rename 返回拒绝访问 | 50/150/300ms 退避重试 3 次；仍失败提示「稍后重试」并提供导出 |
| `state.json` 损坏 | 读取后 `JSON.parse`/zod 失败 | 原文写入 `quarantine/<ts>.json` → 尝试 `last-good.json` → 再失败用默认状态，但**先提示导出原始数据** |
| `state.json.tmp` 残留 | 启动扫描 | 直接删除临时文件；`state.json` 不受影响 |
| `last-good` 同时损坏 | 两级加载均失败 | 进入只读恢复模式：默认状态仅用于展示，**禁止自动保存**，保留两个原始文件，引导用户打开数据目录取证或导入备份 |
| 迁移失败 | 迁移函数抛错 | 不写盘，展示错误与版本号，提供「导出原始文件」 |
| 数据文件被外部修改 | 窗口聚焦时比对 mtime/size/revision | 6.7 的冲突条，不自动合并 |
| 关闭窗口时保存未完成 | `onCloseRequested` | 先 flush；失败弹窗「重试 / 导出备份 / 仍要关闭」 |
| 进程被强杀或断电 | 无法检测 | 防抖 + 原子 rename + `last-good`；最多丢失最后一个防抖窗口（≤ 2s）内的编辑 |
| WebView2 缺失或损坏 | 应用无法启动 | 安装包内置离线 WebView2；启动失败时给出系统错误码与离线安装说明 |
| 受控组件输入中间态（如 `1.`） | 输入层校验 | 输入中不落盘，失焦/合法化后再提交，避免持久化无效值 |

### 6.9 导出设计

| 类型 | 扩展名 | 内容 | 典型场景 |
| --- | --- | --- | --- |
| 全量备份 | `.salary.json` | 信封 `kind: full`，全部方案 + 配置 + 设置 | 换机、重装前备份 |
| 单方案 | `.salary-scheme.json` | 信封 `kind: scheme`，仅一个方案输入 | 分享给同事、Offer 对比存档 |
| 仅配置 | `.salary-config.json` | 信封 `kind: config`，列配置 + 预设 + 自定义城市，**不含金额** | 团队统一表格口径 |
| 月度明细 | `.csv` | 按当前列配置输出 12 行 × 可见列 | Excel 核对、留存工资条 |
| 年度汇总 | `.csv` | 各项年度合计与占比 | 汇报、报税参考 |

**JSON 导出规则**

- UTF-8 无 BOM，2 空格缩进，末尾换行。
- 导出前先 `migrate` 到当前版本并校验，保证「导出的文件一定能被当前版本导入」。
- 成功后更新 `meta.lastExportAt`。
- 文件名：`salary_<full|scheme|config>_<方案名>_<yyyyMMdd-HHmmss>.json`；方案名清洗 `[\\/:*?"<>|]` 与控制字符，截断至 40 字符，为空则用 `untitled`。
- 通过 `bridge.exportText` 打开系统保存对话框；默认目录取上次导出目录（记录在 `ui.json`），用户取消返回 `null` 且不报错。
- 写入失败（无权限/磁盘满）保留对话框上下文，提示重试或改选路径。

**CSV 导出规则**

- 编码：UTF-8 **带 BOM**（`﻿`），确保 Excel 直接打开中文不乱码。
- 分隔符逗号，行尾 CRLF，遵循 RFC 4180：字段含 `,`、`"`、换行时用双引号包裹，内部 `"` 转义为 `""`。
- 金额输出原始数值，固定 2 位小数，不加千分位、不加货币符号。
- **公式注入防护**：文本字段（方案名、收入项名、表头）若以 `= + - @ \t \r` 开头，前置单引号 `'`。
- 表头取当前列配置的 `label`（已重命名则用重命名后文本），列顺序与界面一致。
- 文件名同 JSON，扩展名 `.csv`。
- 保存实现：与 JSON 共用 `bridge.exportText`，由 Rust 以 UTF-8 写入用户选择的路径；不再使用 Blob 下载。Excel 打开时按 BOM 识别编码。

### 6.10 导入设计

**处理流水线**

```text
系统打开对话框 / 拖拽文件到窗口 / 粘贴文本
   │  Rust 读取元数据校验 ≤ 20MB；前端二次校验；含 NUL 字节或非 UTF-8 → E_NOT_FILE
   ▼
读取文本（Rust fs → bridge.importText）
   │  JSON.parse 失败 → E_JSON（提示行号/字符位置）
   ▼
信封识别：format === 'salary-calculator-backup'
   │  无信封但形似旧版裸状态 → 包装为 v1 信封并标记「兼容导入」
   │  kind 缺失 → E_FORMAT
   ▼
版本检查：schemaVersion > 当前 → E_TOO_NEW（提示升级应用）
   │  schemaVersion < 当前 → 迁移链升级（失败 → E_MIGRATE）
   ▼
zod 严格校验（strip 未知字段）+ 数量上限
   │  失败 → E_SCHEMA，列出前 5 条错误路径（如 payload.schemes[3].input.incomes[0].amount）
   ▼
引用完整性修复：列 → 收入项、activeSchemeId、重复 key、order 重排
   │  产生 warnings，不阻断
   ▼
生成预览：数量、同名/同 id 冲突、迁移来源版本
   ▼
用户选择合并策略 → 生成 ImportPlan
   ▼
应用：写 pre-import 快照 → 原子写入 state.json → 成功提示（10s 内可撤销）
   │  写入失败 → 回滚内存并报错，原状态不变
   ▼
完成
```

> 拖拽在 Tauri 中通过 `onDragDropEvent` 取得文件路径，再走同一 `importText` 校验链路；浏览器调试模式使用 `File` 对象读取，行为保持一致。粘贴文本走内存字符串，不落临时文件。

**合并策略**

| 策略 | 语义 | 冲突处理 | 适用 / 默认 |
| --- | --- | --- | --- |
| `replace` 覆盖全部 | 用导入内容替换当前状态 | 不适用 | 恢复备份、换机迁移；`kind: full` 默认（需二次确认） |
| `merge-keep-both` 合并保留双方 | 现有 + 导入并存 | 同 id 或同名 → 导入项重命名 `名称 (导入 2026-10-26)` 并重新生成 id | 多设备方案汇总；`kind: scheme` 默认（推荐） |
| `merge-overwrite` 按 id 覆盖 | 同 id 取 `updatedAt` 较新者，新 id 追加 | 同名不同 id 仍保留双方并提示 | 同一用户多端同步 |
| `as-new` 导入为新方案 | 仅对 `kind: scheme` 生效，强制新 id/新名称 | 不覆盖任何现有数据 | 分享方案试用 |

> `kind: config` 只覆盖列配置、预设与自定义城市，不涉及方案；三种 `merge-*` 策略按对象粒度合并即可，`replace` 表示整块替换配置，`as-new` 不适用。

**冲突判定**：`id` 相同，或 `name.trim().toLowerCase()` 相同（中文不转拼音，不做模糊匹配）。预览中必须逐条列出，不能只给数量。

**引用完整性修复**

| 问题 | 处理 |
| --- | --- |
| 列引用的收入项不存在 | 删除该列 + warning |
| `activeSchemeId` 不存在 | 指向第一个方案；无方案则为 `null` |
| 列 `key` 重复 | 保留首个，其余丢弃 + warning |
| `order` 重复/断层 | 按原相对顺序重排为 0..n-1 |
| 名称为空或超长 | 截断/补默认名 + warning |
| 金额为负、超上限、非有限数 | 该字段置 0 并标记，或整条拒绝（按 zod 规则） |

**原子性与撤销**：应用前把当前状态写入 `backups/pre-import/<ts>.json`；写入成功后保留内存中的 `preImportState`，toast 展示 10 秒「撤销」。撤销时写回 `preImportState`，并先把「导入后状态」另存一份快照，避免用户在两个状态间反复操作时丢失任何一方。写入失败（磁盘满/占用）时，内存状态回滚到导入前，`state.json` 不受影响。

### 6.11 安全与隐私

| 风险 | 对策 |
| --- | --- |
| 导入文件包含可执行内容 | 只做 `JSON.parse`，全程无 `eval` / `new Function` / `innerHTML` |
| 原型污染 | zod 显式字段白名单 + `strip`；映射对象用 `Object.create(null)`；拒绝 `__proto__` / `constructor` / `prototype` 作为 id 或 key |
| XSS | 所有用户文本（方案名、列名、收入项名）用插值渲染，禁用 `v-html`；CSV 公式前缀加 `'` |
| 超大文件/数组导致卡死 | 文件 ≤ 20MB（Rust 与前端双重校验）；方案 ≤ 200、单方案收入项 ≤ 100、列 ≤ 200、预设 ≤ 50；超出直接拒绝 |
| 数据外泄 | 运行期除本机 IPC 外无网络请求；生产 CSP `default-src 'self'; connect-src 'self' ipc: http://ipc.localhost`（开发环境额外放行 Vite HMR）；无埋点、无崩溃上报；界面注明「数据仅存本机」 |
| Tauri IPC 权限过大 | `capabilities/default.json` 最小白名单：仅 dialog、opener（限定数据目录）、single-instance；不启用 shell、http、fs 全盘访问；自定义命令显式注册 |
| 路径穿越 | 内部备份操作只接受 `backups/` 下的相对 key，Rust 端 canonicalize 后校验前缀，拒绝 `..`、绝对路径、UNC；导入导出路径只能来自系统对话框或拖拽事件 |
| 本地明文数据 | 依赖 Windows 用户目录 ACL（仅当前用户可读）；共享电脑在界面提示；V1.1 提供加密存储与金额遮罩 |
| 安装包被篡改 | 正式发布使用代码签名；发布页附带 SHA-256 校验和；V1.1 自动更新必须验签 |
| 日志泄露 | 日志只记录错误码、路径与版本，不记录金额、方案名、收入项名；滚动上限 5MB × 2 |
| 校验和伪造 | `checksum` 仅用于发现损坏，不作为安全边界；所有字段仍走 zod |

### 6.12 备份与恢复

- **自动快照**：每天首次成功保存时写 `backups/daily/YYYY-MM-DD.json`，保留最近 14 份；仅当当日状态有变更才写，避免无意义占用。
- **手动备份点**：用户可创建带备注的快照（最多 20 份），在「数据管理」页列出时间、方案数、文件大小与完整路径，支持恢复与删除。
- **恢复流程**：选择快照 → 显示摘要与差异条数 → 二次确认 → 恢复前再存一份当前状态 → 原子写入 → 提示可撤销。
- **目录级备份**：设置页提供「打开数据目录」，用户可整体复制 `state.json` 与 `backups/`；发布说明给出换机步骤。
- **导出提醒**：若 `lastExportAt` 超过 30 天且期间有修改，页头显示一次性提醒「建议导出一份到其他磁盘或网盘」。
- **换机迁移**：全量导出 → 新设备导入（`replace`）→ 校验方案数、激活方案、列配置一致；也支持直接拷贝数据目录（需先退出应用）。
- **同步盘提示**：不建议把数据目录放进 OneDrive 等实时同步盘；如必须，应保证同一时间只在一台机器编辑，并接受 6.7 的外部改动检测。
- **V1.1 可选**：加密备份包、按周自动导出到用户指定目录、备份完整性校验。

### 8.2 持久化与导入导出测试（`tests/unit/persistence`）

| 用例 | 期望 |
| --- | --- |
| 全量导出 → 导入 | 语义深比较相等（忽略 id 重生成、时间戳、checksum） |
| 单方案/配置导出 → 导入 | 仅影响对应范围，其余状态不变 |
| 旧版 fixture 导入 | 自动迁移到当前版本，字段完整 |
| 未来版本文件 | `E_TOO_NEW`，原状态不变 |

| 字段类型错误（`amount: "abc"`） | `E_SCHEMA`，错误路径可定位 |
| 超限数组（5000 方案 / 1000 列） | 拒绝并提示上限 |
| `__proto__` / `constructor` 污染载荷 | `Object.prototype` 未被污染，导入被拒或字段被 strip |
| 列引用不存在的收入项 | 该列被移除 + warning，导入成功 |

| `state.json.tmp` 残留 | 启动清理临时文件，主状态不受影响 |
| 外部进程改写 `state.json` | 窗口聚焦时检测到并弹冲突条，不静默覆盖 |
| 重复启动应用 | 单实例生效，聚焦已有窗口，不产生第二写入者 |
| 写入中途失败（模拟断电/占用） | 原子替换未发生，旧 `state.json` 完整可读 |
| 备份 key 路径穿越（`../`、绝对路径、UNC） | Rust 拒绝并返回错误码 |
| 备份轮转（第 15 天 / 第 21 份） | 淘汰最旧，日快照保留 14 份、手动备份保留 20 份 |
| 二进制/超大文件（伪装 `.json`） | `E_NOT_FILE` / `E_SIZE`，不进入解析 |
| CSV 特殊字符（逗号/引号/换行/`=cmd`） | 正确转义与防注入 |
| CSV 行列顺序 | 与当前列配置一致，隐藏列不导出 |
| 文件名非法字符 | 清洗后合法且不超长 |
| 迁移函数纯性 | 同一输入多次调用结果一致，无存储/时间依赖 |
| 属性测试（fast-check） | 随机方案 export→import 往返恒等 |

### 8.5 桌面 E2E 与冒烟

**UI 流程（Playwright，浏览器调试 + mock bridge）**

1. 录入 → 出表 → 改列配置 → 重新加载 → 方案、列配置、激活方案全部保留。
2. 全量导出 → 清空数据 → 导入 → 数据一致，激活方案与列宽恢复。
3. 拖入非法文件 → 明确错误 → 现有数据不变。
4. 导入同名方案 → 选择「保留双方」→ 两方案并存且可切换。
5. 导入未来版本文件 → 拒绝并提示升级，数据不变。
6. 空数据、全部收入为 0、极端窗口宽度下的布局与空态。

**真实壳层（WebdriverIO + tauri-driver，Windows CI）**

1. 启动 → 新建方案并输入 → 关闭 → 重新启动 → 数据从 `state.json` 恢复。
2. 编辑后 2 秒内用 `taskkill /F` 强杀 → 重启 → 最多丢失 2 秒内编辑，`last-good` 可恢复。
3. 单实例：第二次启动进程 → 聚焦已有窗口，不出现第二个窗口。
4. 导入/导出：测试模式通过 `--test-mode` 指定固定路径，绕过原生对话框完成链路；发布包中该参数不可用。
5. 干净机安装：Windows 10/11 各一台，断网安装（WebView2 离线包），验证启动、保存、卸载后数据保留策略。

## 九、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 社保/个税政策调整 | 计算结果失真 | 政策全部配置化并带 `policyVersion`；页面展示「政策版本与生效日期」；预留政策配置包离线导入开关（不做联网拉取） |
| 各地社保细则差异大（生育并入医疗、大病固定额、公积金上下限） | 覆盖率不足 | 城市配置以「城市 + 险种」二维表建模；V1 内置 Top 20 城市，其余走「自定义比例」 |
| 浮点/取整精度 | 与工资条对不上 | decimal.js + 分项取整策略，与 HR 实际口径核对 |
| 自定义列配置与收入项耦合导致状态错乱 | 表格缺列/重复列 | 列 Schema 以 `key` 为准做幂等同步，加载与导入时去重、清理孤儿列 |
| 12 月 × N 列表格渲染性能 | 卡顿 | 列数 > 30 时启用虚拟滚动；图表组件异步加载；输入防抖 200–300ms 后重算（与持久化的 400ms 防抖独立） |
| 应用数据目录被清理/误删 | 数据不可恢复 | 自动快照 + 30 天导出提醒 + 文档说明「目录级备份」 + 首次启动引导 |
| 磁盘满/目录只读 | 保存失败、停留在旧版本 | 备份裁剪、只读模式、导出引导；保存前检查剩余空间 |
| 外部进程或同步盘改写文件 | 一方修改被覆盖 | 单实例 + 聚焦时 mtime/revision 检测 + 冲突条，不自动合并 |
| Tauri/Rust 能力缺口 | 壳层开发延期 | Rust 仅承担 IO/对话框/单实例，业务全在 TS；先用官方模板跑通最小闭环；预留 2 人日缓冲 |
| 安装包未签名 | SmartScreen 拦截、用户不敢安装 | 内测提供 SHA-256 与安装说明；正式发布前配置代码签名 |
| WebView2 缺失或版本过低 | 应用无法启动 | 安装包内置离线 WebView2，设置最低版本并在启动时检测 |
| 安装/升级失败或卸载误删数据 | 用户数据丢失 | 卸载默认保留 `%APPDATA%` 数据目录；升级前自动备份；发布说明写清路径 |
| 导入文件恶意或畸形 | XSS / 原型污染 / 页面卡死 | 严格 zod 白名单、数量上限、无 `eval`/`v-html`、CSV 注入防护 |
| schema 演进破坏旧数据 | 升级即丢数据 | 迁移链 + 每版 fixture + 降级拒绝 + quarantine 保留原文 |
| 单实例失效/双开 | 两个进程互相覆盖 | `tauri-plugin-single-instance` + 保存前 revision 检测；冲突时保留双方快照 |
| 持久化了派生结果 | 升级后新旧口径不一致 | 只存输入，加载后重算；导出 CSV 时实时计算 |
| 需求蔓延（企业年金、股权、个税汇算） | 工期失控 | 严格按 V1 范围执行，新增项进 Backlog 排 V1.1 |

## 十、验收标准

1. **准确性**：3 份 Excel 样本对拍误差 ≤ 0.01 元；core 单测覆盖率 ≥ 90%，persistence ≥ 85%，Rust 存储层关键路径全覆盖。
2. **完整性**：需求 2.1–2.4 全部功能可用，无阻塞性 Bug（致命/严重级清零）。
3. **持久化**：关闭窗口、强杀进程、重启电脑后，方案/列配置/设置恢复到最近一次成功保存（最多丢失 2 秒内编辑）；`state.json` 采用原子替换，异常时旧文件仍可读；无权限/磁盘满进入只读模式并有可见提示。
4. **导入导出**：全部走系统原生对话框；全量导出→导入往返语义等价；非法文件 100% 被拦截且原数据不变；导入前自动快照，10 秒内可撤销；配置导出不含任何金额字段。
5. **性能**：输入变更到表格重绘 ≤ 200ms（防抖后）；状态写入 ≤ 30ms（200KB 量级）；冷启动到可交互 ≤ 3s（含 WebView2 初始化）。
6. **代码质量**：ESLint 零 error、无 `any`；`cargo fmt` 与 `cargo clippy` 零警告；提交信息符合项目 Conventional Commits 规范。
7. **桌面交付**：NSIS/MSI 安装包可在断网的干净 Windows 10 与 Windows 11 上安装并运行；单实例生效；运行期除本机 IPC 外无网络请求；关于页展示应用版本、政策版本与数据目录。
8. **交付物**：源码仓库、安装包与 SHA-256、`docs/` 下的政策配置说明、数据格式说明（`state.json` 与信封结构）、用户使用说明（含备份/迁移/卸载保留策略）。
