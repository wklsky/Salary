# 薪资计算器 · 项目完全升级方案（V2.0 路线图）

> 目标：在保持「纯本地、可核对、工程账本」气质的前提下，把项目从「能算准」升级为「算得准、看得懂、反推得动、比得清、用得舒服」。

## 一、现状评估

### 已具备（本轮升级的起点）

- **架构**：Vue 3 + Element Plus + Pinia + ECharts；`src/core` 纯函数计算内核，decimal.js 全链路精度；101 个单元测试全绿。
- **业务逻辑**：居民个人累计预扣预缴、非居民按月分项计税、年终奖「单独/并入/部分拆分」三口径对比、五险一金城市基数封顶托底与逐月明细、11 项专项附加扣除（含个人养老金、商业健康险、公益捐赠比例限额）、雇佣阶段（实习/试用/转正）、单月数据覆盖、税后扣款、年度汇算补退税。
- **交互**：录入 7 分区 + 结果 4 分区、方案存档与切换、月度明细行内编辑与反推调整项、列配置抽屉、CSV 导出。

### 诊断（升级要解决的问题）

| # | 方向 | 问题 |
| --- | --- | --- |
| 1 | 业务 | 只有正向计算，无法「期望到手 → 反推税前」，而这正是工资谈判/涨薪时最常用的场景 |
| 2 | 业务 | 年终奖拆分靠 48 点均匀采样 + 档位边界搜索，理论上可能漏掉全局最优解 |
| 3 | 业务 | 方案只能单条应用，无法把「跳槽 A / 跳槽 B / 留任」并排对比 |
| 4 | 业务 | 年终奖单独计税 2027-12-31 到期后无自动降级提示；非居民额外收入口径可再核对 |
| 5 | 业务 | 21 个内置城市，无「自定义城市」入口；政策版本只展示字符串，无变更说明 |
| 6 | 布局 | 年度汇总与图表在 tab 里二选一；月度表宽列无冻结首列；无打印/PDF 视角 |
| 7 | 布局 | 概览页缺少「口径摘要 + 结论」的统一结论带，关键信息分散在卡片与表格 |
| 8 | UI | 无深色模式；空态/加载态/错误态不统一；动效仅数字滚动 |
| 9 | UI | 字号阶梯与间距节奏未完全统一（上一轮已起步，仍需系统化） |
| 10 | 交付 | 仅 CSV 导出，无 Excel/PDF 交付物 |

## 二、升级目标

1. **可信**：每一分钱都能解释——税额分解、跳档提示、汇算差异口径。
2. **好用**：正向算得快、反向推得准、方案比得清、结果导得出。
3. **好看**：一套「工程账本」设计语言贯穿明暗双主题，状态覆盖完整。

三条主线并行，但按依赖关系分阶段推进。

## 三、业务逻辑升级（B 系列）

### B1 目标倒推计算器（P0）

- 入口：录入页工资条下方「我想拿到 ¥X」卡片；结果页概览结论带。
- 能力：输入期望**月度到手**或**年度到手**，反推需要多少税前月薪；支持指定「可调项」（默认工资薪金项，复用 `reverseAdjustIncomeId`）。
- 算法：以应发为变量做单调二分；每次迭代完整跑 `calculateSalary`（含年终奖拆分、社保封顶、税率跳档），处理分段非单调（社保封顶平台期的多解）——返回一个可行解 + 精度提示，并在工资条上直接呈现反推结果。
- 验收：反推值回代后到手与目标误差 ≤ 1 元；社保封顶区间给区间解而非单一值。

### B2 年终奖拆分精确优化（P0）

- 把「税负 − 单独计税金额」函数按税率档位分段线性化，段内极值只可能在端点取得，解析求每段端点并取全局最小。
- 保留现有 48 点采样作为兜底交叉校验（单测断言两法一致或解析法更优）。
- 验收：36000/144000/300000 等临界点附近拆分结果优于或等于旧算法；计算耗时下降。

### B3 方案对比（P0）

- 方案存档升级：支持勾选 2–3 个方案并排对比。
- 对比维度：年度到手、月均到手、个税、五险一金个人、单位成本、税负率；差异高亮。
- 新增「方案对比」视图（L1）+ 对比 CSV 导出。
- 验收：对比数据与单方案结果逐字段一致。

### B4 政策与边界守卫（P1）

- 年终奖单独计税到期（`BONUS_SEPARATE_VALID_UNTIL`）自动降级为并入，并在 UI 说明原因。
- 非居民个人额外收入（劳务/稿酬/特许权）计税口径复核并补单测。
- 跨年周期、重复阶段区间、金额越界等输入防御。

### B5 城市政策与维护（P1）

- 内置城市数据更新到 2026 口径；新增「自定义城市」：基数上下限 + 各险种个人/单位比例可编辑。
- 政策版本面板：版本号、生效日期、变更摘要。

### B6 可解释性面板（P1）

- 每月税额分解：累计应纳、累计已预扣、本期应预扣、跳档月份标记。
- 汇算差异解释：为什么补/退税，由哪几项造成。

### B7 导出增强（P2）

- xlsx（多 sheet：明细/汇总/对比）或 PDF（打印样式，A4 工资条）。
- 方案 JSON 导出/导入（存档迁移）。

## 四、组件布局升级（L 系列）

- **L1 方案对比页**：侧边栏新增入口；2–3 列对比卡 + 差异表格。
- **L2 年度页双栏**：大屏「年度三表 + 图表」并排，小屏堆叠；取消 tab 二选一。
- **L3 月度明细表增强**：首列冻结、合计行吸底、列宽记忆、行内编辑提示强化。
- **L4 概览页结论带**：口径摘要（城市/基数/税率档）+ 到手/税负/汇算三结论 + 趋势图并排。
- **L5 录入页**：分区进度提示（完成度而非重复目录）；工资条下挂目标倒推入口。
- **L6 打印/导出视图**：工资条 A4 打印样式，浏览器直接打印为 PDF。
- **L7 统一空态/加载态组件**：EmptyState + Skeleton。

> 注意：导航去重刚完成（侧边栏是唯一视图入口），L 系列**不新增重复导航**。

## 五、UI 设计升级（U 系列）

- **U1 深色模式（P0）**：现有设计 token 抽成明暗两套（`data-theme` 切换），Element Plus 变量同步覆写，图表主题联动；首次跟随系统，手动选择持久化。
- **U2 排版系统**：字号阶梯 12/13/14/16/18/22/28/34 落地，4px 间距栅格统一卡片内边距与区块间距。
- **U3 状态覆盖**：加载骨架、空态、错误提示、极端数据（全 0/超大额）不破版。
- **U4 动效**：页面切换、卡片 hover、数字滚动已有；统一 `prefers-reduced-motion` 降级。
- **U5 可访问性**：可见焦点环、键盘可达、aria 标签、对比度达 AA。
- **U6 品牌细节**：账本衬线编号、玉石绿高亮、深色下保持「墨蓝 + 玉」的身份。

## 六、实施顺序与验收

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 一 | B1 → B2 → B3 → B4 | typecheck + 单测（新增反推/拆分/对比用例）+ build |
| 二 | U1 → U2 → U3 → U4/U5 | 明暗双主题走查 + 截图 + 单测 |
| 三 | L1 → L2 → L3 → L4 → L6 | 布局走查 + 现有 101 用例全绿 |
| 四 | B5 → B6 → B7 → L7 | 同上 + 导出物验证 |

每阶段结束提交一次 git，保持可回滚。

## 七、风险与边界

- **业务正确性优先**：内核改动必须保持现有 101 用例全绿；新逻辑补对拍用例。
- **深色模式**：需全组件走查硬编码色；图表颜色从 CSS 变量读取，避免两套色表漂移。
- **不做**（保持纯本地）：Tauri 桌面壳、账号体系、云同步、联网政策拉取。
- **性能**：反推与精确拆分涉及多次重算，需保证输入响应 < 100ms（必要时 Web Worker / 缓存）。
