# UI 布局优化设计方案（第三轮）

- 状态：**待确认**（确认后按 A→F 顺序实施）
- 范围：录入设置视图（SetupView）、结果视图（TableView）及相关组件
- 原则：保持「工程账本」墨蓝+玉石绿身份；不动文案与数据结构；不新增依赖

## 一、现状诊断

1. **分区导航弱**：录入视图 7 个分区单列长流，只能靠底部「上一页/下一页」顺序切换，从 07 回 02 要点 5 次；页面内无任何目录/进度提示（进度只写在底部 PagePager）。
2. **页面长短悬殊**：计算周期、高级设置等短表单只有 3~4 行，收入项页却有 12 个月网格+阶段金额，长短页之间滚动与空白都明显。
3. **行内字段对齐不稳**：收入项/阶段卡片内部字段用 flex-wrap，换行时字段漂移、金额列不齐。
4. **窄屏工资条丢失**：≤1200px 时工资条卡片掉到页面底部，录入时看不到实时结果（navbar 虽常驻年度到手，但月度构成/到手月均看不到）。
5. **两视图风格不一致**：TableView 自绘头部（返回+标题+操作）与 SectionPanel 的账本式头部（衬线序号+竖线+meta 胶囊）是两套语言。
6. **概览页信息单薄**：结果概览只有数字卡片，图表全藏在「年度汇总与图表」页的 tabs 里；无年终奖时 bonus 页整页空态。

## 二、设计方案

### A. 录入视图分区目录条（P0）

在分区内容顶部加一条 sticky 横向目录条：`01 计算周期 … 07 高级设置`，已完成打勾、当前项玉色高亮、点击直达任意分区。底部 PagePager 保留（顺序翻页 + 返回结果视图）。

- 实现：SetupView 模板在 .setup__main 顶部新增 stepper，复用现有 navItems 数据与 select-section 事件；sticky top 对齐 navbar。
- 移动端（≤768px）：目录条允许横向滚动，不做下拉折叠（7 项不多，横向滚动最直观）。

### B. 表单密度与字段对齐（P0）

- **AdvancedForm**：≥900px 时改双列 grid，短表单不再拉长页面。
- **InsuranceEditor**：≥1100px 时「社保基数」组与「公积金」组左右并排，保险比例表仍全宽。
- **IncomeEditor** 收入项行内字段改 grid 固定列：名称 `minmax(120px,1fr)` / 金额 `160px` / 发放周期 `118px` /（一次性时）月份 `88px` / 操作按钮 `auto`；窄屏回退 wrap。金额列对齐不再漂移。
- **StageEditor** 阶段卡片 body 同样改 grid 对齐（类型/起止月/停缴险种）。

### C. 结果视图头部统一（P0）

TableView 自绘 head 改为与 SectionPanel 一致的账本式头部：衬线 eyebrow（`月度明细 · 01 / 04`）+ 主标题 + 描述 + meta 胶囊；「表格列」「导出明细」按钮移至头部右侧；返回按钮保留。

### D. 概览页趋势图（P1）

ChartPanel 增加 `mode` prop（`trend | structure | insurance | all`，默认 `all`）；结果概览页在 ResultCards 下方挂一张 `mode="trend"` 的「月度到手趋势」迷你图，年度页保持三张全量。复用同一懒加载 chunk，不增加包体积。

### E. 年终奖引导空态（P1）

无奖金时 bonus 页的 el-empty 改成引导卡：「尚未添加全年一次性奖金」，附「去添加年终奖」按钮，一键跳回录入视图的收入项分区。

- 实现：TableView 向上 emit 导航意图，App 切换视图并把 SetupView 目标分区设为 income（联动小，改动集中在 App/TableView/SetupView 三处）。

### F. 窄屏工资条（P2）

≤1200px 时 PayslipCard 不再掉到底部，改为横向紧凑卡插在分区目录条之后、表单之前：年度到手/月均应发/到手月均等关键数字横排一行，保持录入时实时反馈。
