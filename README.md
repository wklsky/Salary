# 薪资计算器

一个纯前端的中国工资薪金计算工具：录入收入项、五险一金、专项附加扣除与雇佣阶段，实时算出**月度到手、单位用工成本、全年个税与年度汇算差额**。

所有计算在浏览器本地完成，数据只写入 `localStorage`，不上传任何服务器。

## 功能

**界面结构**

采用管理后台布局：左侧深色菜单包含视图切换与当前页面目录，顶部白色导航栏提供面包屑与操作区，下方为标签页视图，内容区在浅色背景上分板块展示。

| 视图 | 内容 |
| --- | --- |
| **录入设置** | 拆分为「计算周期 / 收入项 / 五险一金 / 雇佣阶段 / 专项扣除 / 税后扣款 / 高级设置」7 个独立分页，每页只展示当前板块；右侧常驻实时结果卡，边填边看年度到手、税负与单位成本 |
| **月度明细** | 拆分为「结果概览 / 年终奖建议 / 逐月明细 / 年度汇总与图表」4 个独立分页；逐月明细页可直接编辑表格，点击月份单元格可打开单月编辑 |

- 顶部导航栏包含折叠按钮、面包屑与年度到手 / 方案存档等操作
- 标签页视图切换主视图，左侧菜单切换当前视图的分页，面包屑和「当前板块」随分页同步更新
- 每个分页底部提供「上一页 / 下一页」；录入最后一页可直接进入月度明细，明细最后一页可返回录入设置
- 侧边栏实时展示各分区状态（月数、收入项数、参保城市等），不再把全部内容堆在一条长页面上
- 桌面端可将侧边栏收起为图标栏；窄屏下改为抽屉菜单，内容区仍保持一屏高度内部滚动
- 切换视图或分页不会丢失录入，顶栏常驻展示年度到手

**组件拆分**
- 页面外壳：`AdminSidebar`（深色菜单，唯一导航入口）、`PagePager`（账本式分页页脚）
- 录入设置：`SectionPanel`（`el-card` 章节容器）+ `PeriodForm` / `IncomeEditor` / `InsuranceEditor` / `StageEditor` / `DeductionEditor` / `PostTaxDeductionEditor` / `AdvancedForm`
- 实时结果：`PayslipCard`（独立工资条组件）
- 月度明细：`ResultCards` / `BonusAdvice` / `MonthlyTable` / `AnnualTable` / `ChartPanel`
- 基础交互优先使用 Element Plus：`el-card`、`el-tabs`、`el-breadcrumb`、`el-form`、`el-table`、`el-drawer`、`el-button`、`el-tag`、`el-alert`、`el-empty`
- 表格单元格的行内编辑保留原生输入框，以保证 12 个月 × 多列实时编辑的性能

**计算周期**
- 以**起始月 + 计算月数**定义区间，月数 1-12，最长一年
- 区间不得跨自然年：起始月 6 月时最多计算 7 个月；跨年周期请分两段录入

**单月调整**
- 在月度明细点击某个月，可单独设置该月各收入项金额、社保缴费基数与备注
- 调整后系统自动重算该月工资，抽屉顶部实时显示该月应发 / 社保 / 个税 / 到手
- 单项可「还原」回到按规则自动计算的口径，也可一键清空该月所有调整

**自定义表头**
- 表格列可自由显示 / 隐藏 / 拖拽排序 / 重命名 / 保存为预设
- **可新增自定义列**（如「项目奖金」「补贴」），自带 12 个月数值，在单月编辑里逐月填写
- 自定义列可选择是否计入应发，计入时可进一步选择是否计税、是否计入社保缴费基数；不计入时该列仅作展示

**绩效计分**
- 收入项可切换为「按绩效分数计价」：每分金额由用户自定义，逐月填写分数
- 当月金额 = 当月分数 × 每分金额；分数列与金额列双向联动，修改任意一侧自动更新另一侧
- 计分制收入项同样参与应发、计税、缴费基数与总扣款计算

**表格内编辑与反推**
- 月度明细中的金额、分数、备注单元格可直接编辑，回车或失焦后生效
- 带 ⇄ 的列支持反推：修改应发工资 / 实发工资 / 个税，自动反推调整工资项；修改缴纳额，自动反推缴费基数
- 水电费、管理费等税后扣款修改后，税后扣款合计、总扣款与实发工资自动联动
- 反推所用的调整工资项可在「表格列 → 反推调整项」中指定，留空自动选择第一个逐月计税工资项
- 按回车或失焦生效，按 Esc 取消本次编辑；输入值与当前结果一致时不会触发无意义的反推
- 默认只展示在职月份，可切换「显示全部 12 个月」；月份列固定在左侧、实发工资固定在右侧
- 表格高度随浏览器视口自适应，短屏时自动收缩并在表格内部滚动

**收入与阶段**
- 收入项可增删，区分逐月发放与一次性发放
- 每项可配置是否计入社保基数、是否免税、是否**为非现金收入**
- 餐补、饭票、购物卡等非现金收入计入应发合计与应纳税所得额（参与计税），但**不作为实际发放工资，不计入到手**
- 月度明细同时展示「应发合计」与「实际应发工资」：前者含餐补等税前收入，后者为实际发放的现金工资
- 金额可按月不同（如按出勤浮动的餐补），逐月填写 12 个月
- 雇佣阶段（实习期 / 试用期 / 转正后）按月份划分，各阶段可分别设置发放金额与是否发放
- 阶段可整体不缴五险一金（实习期），也可单独停缴个别险种——例如试用期只缴五险、转正后才缴公积金
- 试用期工资低于转正后 80% 时给出合规提示

**五险一金**
- 内置 20 个城市政策 + 自定义兜底，含基数上下限与各险种比例
- 社保基数支持四种口径：当年应发（近似）、上年度月均（法定）、手动指定、下限托底
- 公积金基数可独立于社保配置，封顶托底单独开关
- 各险种个人 / 单位缴纳额分列展示
- 公积金缴费额按元取整，其余险种保留到分
- 社保基数与公积金基数可按月分别核定，支持「社保基数上调、公积金不变」
- 大病医疗固定额由用户按当地标准填写，默认不计入

**个税**
- 居民个人累计预扣预缴，支持年中入职、年内离职
- 非居民个人按月单独计税，不适用居民个人的年度汇算
- 年终奖三种口径：单独计税、并入综合所得、自动择优（含部分单独计税的拆分搜索）
- 额外收入（劳务报酬 / 稿酬 / 特许权使用费）按次减除费用后预扣，年度汇算并入综合所得
- 「多发反而少拿」无效区间提示
- 每月减免税额（残疾、孤老、烈属等减征政策），预扣与汇算口径一致
- 年度汇算口径（仅居民个人），输出应补 / 应退税

**专项附加扣除**
- 11 个项目：婴幼儿照护、子女教育、继续教育（学历 / 职业资格）、住房贷款利息、住房租金、赡养老人、大病医疗、个人养老金、商业健康险、公益捐赠
- 赡养老人区分独生子女（3000 元/月）与非独生子女分摊（≤1500 元/月）
- 大病医疗自动扣除 15000 元起付线，年度上限 80000 元，仅在汇算时扣除
- 公益捐赠按应纳税所得额 30% 限额动态计算
- 住房贷款利息与住房租金互斥校验

**税后扣款**
- 支持任意税后扣款项（默认「水电费」「管理费」，对应宿舍扣款场景），逐月手动填写
- 在个税与五险一金之后从实发工资中扣除，不影响应纳税所得额与缴费基数
- 每项可单独设置是否「计入总扣款」；取消后该列仅展示，不减少实发工资
- 月度明细自动输出各扣款项、税后扣款合计、总扣款与实发工资，并支持单月编辑
- 总扣款 = 缴纳共计（五险一金个人） + 个税 + 税后扣款；实发工资 = 应发工资 − 总扣款

**结果与数据**
- 月度明细表、年度汇总表、图表看板
- 内置 5 套列预设（极简、个人常用、工资表（含宿舍扣款）、财务口径、HR 全量明细）
- 月度明细导出 CSV（带 BOM，Excel 打开中文不乱码）
- 配置导出 / 导入 JSON，支持多方案存档切换；导出内容含计算设置、收入/扣除数据、表格列配置与自定义列金额

## 计算口径

### 累计预扣预缴

居民个人工资薪金按年累计计算，每月：

```text
累计应纳税所得额 = 累计综合所得 − 累计三险一金 − 累计专项附加扣除 − 5000 × 在职月数
累计应纳税额     = 累计应纳税所得额 × 预扣率 − 速算扣除数
本月应预扣       = 累计应纳税额 − 累计已预扣 − 累计减免税额
```

- 减除费用按**本单位任职月数**累计，年中 7 月入职时 7 月只扣 5000 元，而非 35000 元
- 本月应预扣为负数时当期不退税，也不回冲累计已预扣额，差额留到年度汇算处理
- 在职月数同时受入职月份与离职月份约束

### 年终奖

一个纳税年度内**只允许一笔**奖金享受单独计税，其余并入综合所得。

单独计税：`奖金 ÷ 12` 定位月度税率表级距，`应纳税额 = 奖金 × 税率 − 速算扣除数`。

「自动择优」除比较两种纯口径外，还会搜索「部分奖金单独计税、其余并入」的拆分方案，取全年税负最低者。拆分搜索会在月度税率表档位边界（×12）附近取点，因为边界值正是无效区间的左端点。

### 额外收入（劳务报酬 / 稿酬 / 特许权使用费）

这三类与工资薪金分属不同税目，**按次预扣**，不参与工资薪金的累计预扣：

```text
减除费用   = 每次收入 ≤ 4000 ? 800 : 收入 × 20%
应纳税所得额 = 收入 − 减除费用
劳务报酬   = 应纳税所得额 × 预扣率 − 速算扣除数   // 20000/50000 分档，20%/30%/40%
稿酬预扣   = 应纳税所得额 × 70% × 20%           // 减征 30%
特许权使用费 = 应纳税所得额 × 20%
```

年度汇算时按**收入额**并入综合所得：劳务报酬、特许权使用费为减除费用后的余额，稿酬再减征 30%。因此高预扣的劳务报酬通常在汇算时产生退税。

### 年度汇算

在月度预扣结果上加入**仅汇算可扣除**的项目（如大病医疗）与**额外收入额**后重算：

```text
汇算应纳税额 = (综合所得 + 额外收入额 − 三险一金 − 全部专项附加扣除 − 60000) × 年度税率 − 速算扣除数
汇算差额     = 汇算应纳税额 − 工资薪金已预扣 − 额外收入已预扣     // 正数补税，负数退税
```

公益捐赠的扣除上限取「未扣除捐赠前的应纳税所得额 × 30%」。

### 非居民个人

按月收入单独计税，不累计、不享受专项附加扣除，适用按月换算后的综合所得税率表。奖金并入发放当月工资计算。

## 目录结构

```text
src/
├── core/            # 计算内核，纯函数，不依赖 Vue
│   ├── tax.ts       # 个人所得税：累计预扣、非居民、汇算
│   ├── bonus.ts     # 年终奖单独计税、无效区间
│   ├── insurance.ts # 五险一金逐月缴纳
│   ├── stage.ts     # 雇佣阶段解析
│   ├── money.ts     # Decimal 封装与取整
│   ├── otherIncome.ts # 劳务报酬/稿酬/特许权使用费预扣
│   └── index.ts     # 编排：择优、拆分搜索、年度汇总
├── config/          # 政策数据与展示配置
│   ├── policy.ts            # 版本、减除费用、免责声明
│   ├── taxBrackets.ts       # 年度 / 月度税率表
│   ├── cities.ts            # 城市社保公积金政策
│   ├── specialDeductions.ts # 专项附加扣除目录与限额
│   ├── stages.ts            # 阶段定义与区间校验
│   ├── columns.ts           # 表格列 schema
│   └── presets.ts           # 收入项与列预设
├── stores/          # Pinia：录入数据、设置、列配置
├── views/           # 页面层：视图组装与页面级交互
│   ├── SetupView.vue    # 录入设置（分区目录 + 章节面板 + 工资条）
│   ├── TableView.vue    # 月度明细（概览 + 明细表 + 年度汇总）
│   └── CompareView.vue  # 方案对比（当前录入 vs 已保存方案）
├── components/      # 组件层：可复用 UI 组件，不持有页面编排逻辑
│   ├── common/      # SectionPanel / PagePager / MoneyInput 等通用组件
│   ├── setup/       # PeriodForm / AdvancedForm / PayslipCard / TargetReverseCard
│   ├── layout/      # App 外壳组件 AdminSidebar
│   ├── month/       # 单月数据编辑抽屉
│   ├── income/ insurance/ deduction/ stage/  # 各类录入面板
│   └── result/ table-config/ chart/          # 结果表、列配置、图表
├── composables/     # 计算结果 computed、导入导出
├── types/           # 类型定义，按领域拆分
└── utils/           # 列取值、格式化、ID
tests/unit/          # 内核单测、列取值、组件挂载、应用冒烟
docs/                # 开发计划书
```

分层约定：`views/` 只做页面组装与页面级交互；`components/` 是复用组件、不持有页面编排；`core/` + `config/` 是纯计算与政策数据，不依赖任何 UI 代码，可单独测试或移植；`stores/` 负责状态与持久化；页面通过 `composables/` 与 store 拿数据，不直接触碰计算内核。

## 免责声明

各地社保、公积金比例与基数上下限每年调整，本工具内置数据为参考值。计算结果不等同于税务申报依据，请以当地社保局、税务局最新公布口径及单位实际申报为准。
